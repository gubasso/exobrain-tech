# Task: runner

Move the project from pre-commit to prek, so prek is the only hook runner, and install the prek shims. Chapter 03 and chapter 04 give the reasons: `$EXOBRAIN_TECH/programming/project-bootstrap/03-local-dev-environment.md` and `$EXOBRAIN_TECH/programming/project-bootstrap/04-quality-gates.md`.

## Pre-flight

1. Find each use of the pre-commit runner in the tracked files: `git grep -nE '\bpre-commit (run|install|autoupdate|clean|gc|try-repo)\b|pkgs\.(pre-commit|"pre-commit")|pre-commit/action|pip install .*pre-commit|uv tool .*pre-commit|pipx .*pre-commit'`. A list item `pre-commit` in a `with pkgs;` list of the flake counts too. The file name `.pre-commit-config.yaml` and the hook type `pre-commit` are not uses of the runner.
2. Find each use of prek in the devshell. The host supplies prek, so a devshell copy goes too.
3. Read each file of the hooks folder, `git rev-parse --git-path hooks`, other than a `.sample` file. The second line tells who installed it:
   - `# File generated by prek` is a prek shim.
   - `# File generated by pre-commit` is a pre-commit hook.
   - Any other file is a hook that neither runner installed. Stop and ask the operator what it does and whether to keep it.
   - A `<type>.legacy` file is a hook that an earlier plain `prek install` moved aside, and prek runs it after its own shim. Read it the same way.

Where no use of pre-commit is left, every hook is a prek shim, and no `.legacy` file exists, skip the execution.

## Execution

1. Remove `pkgs.pre-commit` and any `prek` package from the devshell. The hook `no-hook-runner-in-flake` of exobrain-tech judges the result.
2. Move each recipe, script, and documented command to prek: `pre-commit run` to `prek run`, `pre-commit install` to `prek install`, and `pre-commit autoupdate` to `prek update`. Keep each argument, such as `--all-files` or `--hook-stage pre-push`.
3. Move CI to the form of `$EXOBRAIN_TECH/programming/project-bootstrap/05-ci.md`. Replace each step that installs pre-commit with `j178/prek-action` and `install-only: true`, pinned by commit SHA. Each check step runs `prek run` inside the devshell.
4. Make sure that the configuration names `minimum_prek_version: "0.5.7"`, the floor of the sets, or a newer one that the project needs. The `sets` task takes `default_install_hook_types` and `default_stages` from the common set.
5. Delete each pre-commit hook and each `.legacy` file that pre-commit installed. Keep each hook that the operator chose to keep, and write down where it lives now.
6. Run `prek install --force`. With no `--hook-type`, prek installs each type of `default_install_hook_types`. `--force` replaces a shim that exists. A plain `prek install` keeps an old hook as `<type>.legacy` and runs it after its own shim (the prek repository, `v0.5.7/crates/prek/src/cli/install.rs`). A linked worktree shares the hooks folder of the main checkout, so one install covers every worktree.
7. Commit the configuration, the flake, and each recipe as `build(hooks): run the git hooks with prek alone`, and CI as `ci: run the hook stages with prek`.

## Post-flight

1. The search of pre-flight step 1 finds no use of the runner.
2. Each file of the hooks folder, other than a `.sample` file, starts with the prek line.
3. `prek run --all-files` runs. A config that pre-commit alone accepted can fail here. Report the hook and its output.
